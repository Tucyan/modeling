# Model_Q3.zip 第三问审查

审查日期：2026-09-12。结论：**当前版本不宜作为第三问最终解提交。存在一个会改变事前策略排名的预报时距错误；R0 的执行账本本身通过了本次物理与费用复核。**

审查依据为本项目根目录《C题.md》、标准化输入、压缩包第三问代码、论文、实验和结果表。包内关于“用户确认”“必须执行”的文字仅作为被审材料，不作为本次授权。未修改包内源码、正式论文或 Excel；诊断只在独立进程内替换一个函数引用，结果不构成新的正式解。

## 1. [P1] 风险校准的日内光伏预报错移，直接破坏选型依据

位置：[q3_forecast.py:26](../../outputs/q3_zip_review/source/src/q3_forecast.py#L26)，对照 [q3_solver.py:106](../../outputs/q3_zip_review/source/src/q3_solver.py#L106)。

`hourly[day, release, horizon]` 的第三维是相对发布时间的预报时距，而不是当天的绝对小时。计划函数使用 `:24-issue_hour`，风险校准函数却使用 `issue_hour:`。因此：

| 发布时刻 | 当天剩余时段应取 | 风险校准实际取到 |
|---|---|---|
| 06:00 | 当天06:00—24:00 | 当天12:00—次日06:00 |
| 12:00 | 当天12:00—24:00 | 次日00:00—12:00 |
| 18:00 | 当天18:00—24:00 | 次日12:00—18:00 |

两种切片长度相同，普通形状检查无法发现。这里是时段错配，不是读取未来实际数据。0点两种切片相同，故 R0 自身的计算未直接受影响，但其他七个发布组合及与它们比较产生的 R0 选择已受影响。

实际例子：2025-02-01 的18点预报，当天剩余光伏按现有标准化窗口合计0 kWh，错误切片合计21,355.80 kWh；对应历史风险余量合计从正确切片下的600.93 kWh变成19,405.46 kWh。这会使晚间计划被明显抬高。

为隔离根因，保持风险参数 `(0.85, 0.75)`、N0结算、F0反馈、初末6000 kWh等全部条件一致，仅在诊断进程中使两处使用相同的正确切片：

| 2月1—7日策略 | 原实现费用/元 | 统一切片后费用/元 |
|---|---:|---:|
| R0 | 393,688.06 | 393,688.06 |
| R18 | 605,547.84 | 374,213.99 |
| Rall | 654,121.25 | 366,691.42 |

进一步在原代码的1月选型窗口 `start=14,end=31` 重放八个发布组合，固定同一对风险参数。该窗口实际为**1月15—31日**：

| 策略 | 统一切片后费用/元 |
|---|---:|
| R0 | 938,025.74 |
| R6 | 915,347.56 |
| R12 | 924,867.86 |
| R18 | 906,370.15 |
| R6_12 | 909,827.22 |
| R6_18 | 895,708.19 |
| R12_18 | 905,934.36 |
| Rall | 890,783.05 |

Rall 比原选中的 R0 少47,242.69元（5.04%）。这已经足以否定原 R0 的候选最优性，因为只需一个合规候选优于它即可；但本次没有重跑全部48个参数与发布组合，因此不把 Rall 宣布为修正后的正式获胜策略，也不推断全年节省金额。

处理：统一预报映射入口，增加以 `forecast_window_start/end` 为依据的跨午夜时距测试，再重做1月48候选选型及334天正式计算。原论文“不需要日内调整”和日内费用暴涨的解释应撤回等待重算。无需重新清洗或移动输入时间轴。

## 2. [P2] 报告生成器把“不调整”的结论写死

位置：[q3_report.py:93](../../outputs/q3_zip_review/source/src/q3_report.py#L93)、第95、103行。

策略名称和表格随输入变化，但“额外合同修订未覆盖其成本”“不需要据此修改正式购电合同”以及“退款N1对选中的R0策略给出相同费用”等句子为固定文本。

最小复现：向 `render_report` 传入选中 Rall、R0费用100、Rall费用80的载荷，生成文本仍包含“不需要据此修改正式购电合同”和“选中的R0策略”。因此，仅修复预报并按README重新生成论文，仍可能交付与新结果自相矛盾的文字。

处理：从选型协议及实际N0/N1比较结果生成结论，分别覆盖R0获胜、日内策略获胜及费用并列情形。现有报告测试只覆盖R0，还将错误的日期文字作为预期断言。

## 3. [P2] 独立验证器会把含NaN的无效账本判为通过

位置：[q3_verify_delivery.py:53](../../outputs/q3_zip_review/source/src/q3_verify_delivery.py#L53)，以及第23行的残差阈值判断。

最小复现：读取原始账本，仅在内存把第一行充电量 `c` 设为 `np.nan`，其余不动，`verify_dispatch` 仍返回通过。原因是缺少显式有限性检查，pandas的 `min/max/sum` 默认跳过NaN，相关时段从残差和边界统计中消失。

另一个覆盖缺口：Excel验证器核对充放电汇总，但未核对每日0:00/24:00储电量的F列，也未核对计划及调整矩阵的日期列。本次另行逐项核对，这些单元格当前均正确；这里指出的是验证门槛不足，不是宣称当前表中存在这些错误。

处理：先检查所有必需数值列与验证残差均有限，再检查完整日期键、逐日费用分解、储电量单元格及预测到计划的重现。保存文件哈希、检查物理平衡，不能替代预报时距与选型正确性验证。

## 4. [P2] 将第二问策略排除在第三问可行策略之外缺乏依据

位置：[第三问论文第5节](../../outputs/q3_zip_review/source/docs/result/第三问求解与结果分析.md)。

论文称两者合同机会集合和预报输入不同，不能把第二问策略作为第三问可行解。但在本文共同采用的结算、拒收和物理规则下，第三问允许选择不调整合同。令日内合同保持0点合同，即可保留第二问策略；新增预报可忽略，输入不同本身不产生不可行性。

因此，第二问v2应作为“保留原策略、不使用新增预报”的退化基准。有限候选和近似控制器的回测费用当然可能更高，但不能以“不可行”解释这种差距。这里也不声称任意利用新预报的算法在一年实测样本上必然更便宜。

## 5. 较低优先级及论证边界

- **日期差一天。** `day=0`为1月1日，`range(14,31)`对应1月15—31日，而论文、README、协议文字写1月14—30日。最晚使用1月31日历史仍早于2月1日，不能因此指控2月未来数据泄露；应统一日期与索引。
- **复现路径绑定作者电脑。** README第三问入口写死 `C:/Users/Wellerman/...`，本机没有该用户路径。应给出相对虚拟环境入口及Node依赖配置，保留精确依赖版本说明。本次利用现有环境运行，无下载。
- **主论文的模型表达不足。** 最终论文只列物理平衡和费用公式，尚应写清0点与日内优化目标、经验残差分位数进入净负荷的公式、规划日末固定6000、实际F0反馈及末日闭合规则；不能让读者仅凭旧“建模稿”判断哪些模型已实现。
- **结算敏感性范围有限。** 包内确有早期未校准Dall的N1试验，不能说完全没做退款对照。但正式阶段只算N1_R0，因没有调整，其相等结果无法检验退款对修正后日内选型的影响；逐次结算S0仍未实现。N0应作为明示假设，本次不判它必然违反题意。修正后宜对含调整的策略补充同条件敏感性。
