# Q4 最终审查补强设计

## 1. 目标与边界

本任务只在冻结的第四问正式结果上进行派生分析、独立验证和论文材料生成。禁止修改 Q4 的优化目标、约束、执行控制器、正式求解流程和正式结果；禁止修改 Q1—Q3 的代码、结果、数据和文档；禁止训练新模型或使用未来真实价格生成决策。

正式基线为 `outputs/q4_final/` 中 N0 主结果及 N1 既有敏感性结果。所有新增结果写入 `outputs/q4/`，所有新增报告写入 `docs/q4/`。分析脚本放入 `analysis/q4_review/`，不得导入或调用现有优化入口执行新求解。

## 2. 冻结保护

分析开始与结束时分别计算以下对象的 SHA-256：

- Q1—Q3 的 `src/` 专属代码、正式输出和正式论文；
- Q4 核心 `src/q4_*.py`、共享求解器和控制器；
- `outputs/q4_final/` 下全部正式账本、协议、工作簿和核验记录；
- 标准化输入数据。

结束时逐文件比较哈希。任何保护对象变化均使验证失败。因为当前目录没有 `.git`，哈希清单是本次任务的主要冻结证据。

## 3. 数据证据分级

所有结论分为三类：

1. **已证实**：可由冻结账本、协议、预测记录或工作簿独立复算；
2. **证据不足**：所需变量未在冻结产物中保存，且因禁止重算不能补齐；
3. **仅实验设计**：给出公平比较口径，但不宣称已经取得数值结果。

不得用代码中的瞬时变量、论文文字或重新求解的结果冒充冻结产物证据。

## 4. 分析模块

### 4.1 基线快照

扫描并记录 Q4 入口、正式协议、优化变量、目标函数、约束、F0 执行策略、结果文件、逐槽账本、预测记录和验证脚本。引用文件路径和 SHA-256，不修改原文件。

### 4.2 规划—执行一致性

冻结正式账本保存了实际 `c`、`d`、`E_start`、`E_end`，但没有保存日前优化的 `c_plan`、`d_plan`、`SOC_plan`。因此：

- 输出字段可用性清单；
- 将计划—实际偏差标记为不可识别，不生成伪数值；
- 独立按冻结的 F0 规则逐槽重放，用账本中的合同、负载、PV、期初 SOC 和末日闭合条件重建实际充电、放电、紧急购电、弃电与下一时刻 SOC；
- 统计重建值与账本值的全年均值绝对误差、最大绝对误差和月度误差。

F0 重放只能证明执行器与正式账本一致，不能替代优化计划与实际执行的偏差结论。

### 4.3 收益来源消融

- B0：N0 正式 Q4-2；
- B1：读取现有 1 月 15—31 日 Q4-3/R0 候选，作为“无日内调整”的局部证据；
- B2：N0 正式 Q4-3，并读取同一 1 月窗口的 Rall 候选。

全年只报告 B0 和 B2，因为没有冻结的全年 B1。1 月 B1 与 B2 使用现有候选分数，明确其只支持校准窗口内的机制分析。正式 Q4-3 的 `price_gamma=0`，因此日内价格误差修正对正式全年结果的直接贡献为 0；PV 信息与合同调整的全年独立贡献因缺少正交冻结回放而不可分离。

### 4.4 全年稳定性与尾部案例

由 N0 正式日账本计算 `daily_delta_cost = cost_Q4_2 - cost_Q4_3`，输出月度汇总、每日分布、累计节费和正收益天数占比。按日收益排序选择最大收益 TOP5 和最大损失 TOP5，从逐槽账本输出价格、PV、SOC、`q-g`、Q4-2/Q4-3 购电变化和紧急购电曲线，并保存原始案例表。

### 4.5 价格预测经济评价

从冻结协议读取 P0p、P1p、P2p 的 MAE 与 RMSE。只有获选 P2p 存在正式全年调度成本；P0p/P1p 标记为未保存，不运行新回放。报告不得根据单一 P2p 成本断言三个模型的经济排序，只能评价统计误差排序及当前经济证据是否充分。

### 4.6 终端 SOC 敏感性

不运行新求解。文档给出硬约束、绝对偏差软惩罚和 48 小时滚动窗口的统一初始 SOC、评价期、结算方式、因果信息边界、指标与公平比较要求，并明确当前冻结结果只覆盖现有硬目标/评价末日闭合口径。

### 4.7 验证增强与预测审计

- 独立复算逐槽母线平衡、SOC 递推、边界、功率、互斥、结算费用、每日费用和全年费用；
- 将四份正式工作簿按模板映射逐个数值单元格与账本/工作簿载荷比较，记录单元格数、最大误差和首个差异；
- 从冻结的 Q2 预测缓存、附件 3 PV 发布文件和 Q4 价格预测记录整理 `load_prediction`、`pv_prediction`、`price_prediction`；
- 每条记录保存预测日期、发布时间、目标时段、历史窗口或来源范围、已观测前缀长度和源文件哈希；
- 对已保存价格预测执行未来扰动不变性检查。扰动仅作用于验证副本，不写回正式输入。

## 5. 文件职责

- `analysis/q4_review/frozen_inputs.py`：只读路径、结构检查、哈希与冻结数据加载；
- `analysis/q4_review/analyze_frozen_results.py`：一致性、消融、稳定性、案例和价格指标派生；
- `analysis/q4_review/build_prediction_audit.py`：预测输入与历史窗口审计；
- `analysis/q4_review/render_review_reports.py`：从派生 CSV/JSON 生成 Markdown 和图表；
- `analysis/q4_review/validate_frozen_results.py`：F0 重放、物理/费用复算、Excel 逐格核验、哈希保护和输出完整性门禁。

允许新增 CSV、JSON 和 PNG 作为分析结果。不得新增或覆盖正式 Excel。

## 6. 验收标准

- 保护对象结束哈希与开始哈希完全一致；
- 所有派生表均可追溯到冻结文件，日期覆盖 334 天且无重复；
- 日收益合计与正式 Q4-2/Q4-3 总成本差一致，容差为 `1e-6` 元；
- F0 重放、物理平衡、SOC 递推和费用复算最大误差不超过 `1e-6`；
- 四份正式 Excel 的所有应填数值单元格均被核对，最大误差不超过 `1e-6`；
- 价格预测的历史终点不晚于预测日，日内已观测前缀不超过发布时间；
- 报告中的缺失实验明确标注，不以设计值、代码重建值或短窗口值代替全年结果；
- 最终报告逐项回答执行一致性、收益来源、稳定性和未来信息泄漏，并列出论文应保留及不应声称的结论。
