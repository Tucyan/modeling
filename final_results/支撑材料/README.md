# 成果支撑材料

本目录用于支撑 `final_results/` 中的论文和正式结果，提供从原始附件、数据处理到模型复现和结果核验所需的材料副本。它面向审阅、复核和复现，不替代 `final_results/results/` 中的正式交付文件。

## 目录结构

- `核心程序/`：与四问正式结果直接相关的求解、预测、控制、回测、报告、工作簿和独立核验程序。每个程序的详细用途见其中的 `README.md`。
- `主要输出/`：正式 Excel、结果摘要、选型协议、预测缓存、指定日期表和独立核验 JSON；内容与 `final_results/results/` 对应。
- `原始模板/`：题目提供的、尚未修正时间轴的原始结果模板。
- `原始数据/`：原始附件 1—4 和原始题目 PDF。这里的文件不做修改。
- `处理后的数据/`：由原始附件标准化得到的 CSV、数据字典、质量报告、标准化 Excel 和修正后的结果模板。
- `处理数据的代码/`：`process_data.py` 及其依赖清单，用于从 `原始数据/` 重新生成 `处理后的数据/`。

## 数据处理复现

在本目录下执行：

```powershell
python -m pip install -r .\处理数据的代码\requirements.txt
python .\处理数据的代码\process_data.py
```

脚本默认以 `C_final_delivery/` 作为工作根目录；本支撑材料目录按同样的 `raw_data/`、`data_csv/`、`templates/` 结构保存副本。若直接在本目录运行，需要将当前目录映射为 `C_final_delivery/`，或在原仓库的 `C题_标准化数据与修正模板\C_final_delivery\` 下运行原入口。

## 使用关系

1. `原始数据/` 是输入证据，不应覆盖或手工修改。
2. `处理数据的代码/process_data.py` 生成标准化数据和修正后的模板。
3. `核心程序/` 使用处理后的数据进行预测、优化、回测和核验。
4. `主要输出/` 保存与论文一致的正式结果和审计凭证。

## 维护规则

- 每次更新必须先在仓库原始 `outputs/` 和 `C_final_delivery/` 完成处理、求解及独立核验，再同步替换本目录对应副本。
- `主要输出/` 必须与 `final_results/results/` 保持同一版本，不得混用旧结果。
- `原始数据/` 和 `原始模板/` 只允许增加有来源的新原件，不允许修改已有文件。
- 不复制测试套件、讨论稿、smoke/ablation 实验、inspect 文件或大体积中间回放到本目录。
